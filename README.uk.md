# MCP-сервер Obsidian для Cloudflare Workers

[English](README.md) | **Українська**

MCP-сервер (Model Context Protocol), який дає AI-асистентам доступ до вашого
сховища Obsidian для читання й запису. Працює на Cloudflare Workers, зберігає
нотатки в **Koofr** (або будь-якому WebDAV), авторизація — **OAuth 2.1**.

Запитайте «які в мене завдання на сьогодні» — отримаєте відповідь із реального
сховища. Скажіть «додай завдання подзвонити в банк» — нотатку буде оновлено.

```
Claude / будь-який MCP-клієнт
        │  OAuth 2.1 + Streamable HTTP
        ▼
  Cloudflare Worker  (/mcp)
        │  WebDAV (Basic auth)
        ▼
  ваше WebDAV-сховище  ──►  Koofr Sync / Remotely Save
                                  │
                                  ▼
                            сховище Obsidian
```

## Навіщо

Obsidian тримає нотатки на пристрої, офіційного віддаленого API немає. Цей
проєкт дає асистенту вузький і контрольований доступ до нотаток — без доступу до
всього диска, без платного синку й без сервера вдома.

Cloudflare Workers обрано тому, що безкоштовного тарифу достатньо для особистого
використання, не треба обслуговувати машину, а холодний старт швидкий.

## Можливості

| Інструмент | Що робить |
|---|---|
| `create_note` | Створити нотатку. Ніколи не перезаписує — додає ` 2`, ` 3` |
| `append_note` | Дописати текст у наявну нотатку |
| `read_note` | Прочитати нотатку за шляхом |
| `search_notes` | Пошук за назвою файлу й вмістом, рекурсивно |
| `list_notes` | Показати вміст теки |
| `daily_note` | Дописати в `Daily/YYYY-MM-DD.md`, створить за потреби |
| `today_tasks` | Відкриті завдання на сьогодні, за бажанням по всьому сховищу |
| `add_task` | Додати завдання `- [ ]` зі строком і пріоритетом |
| `create_folder` | Створити теку, зокрема вкладену |
| `ping` | Перевірити доступ до WebDAV і правильність шляху |

Завдання у форматі **Obsidian Tasks**: `- [ ]`, `- [x]`, строк `📅 YYYY-MM-DD`,
пріоритет `⏫ 🔼 🔽`.

## Безпека

- **OAuth 2.1** з динамічною реєстрацією клієнта (DCR) — клієнт реєструється сам.
- Для входу потрібен пароль власника (`OWNER_PASSWORD`). Знати адресу воркера
  недостатньо.
- Токен доступу живе 1 годину, токен оновлення — 30 днів.
- **Денний ліміт запису** (`DAILY_WRITE_LIMIT`, лічильник у KV) — навіть із
  дійсним токеном не вийде записати більше ніж N нотаток за добу.
- **Немає інструментів видалення чи перейменування.** Асистент не може знищити
  ваші нотатки.
- Назви файлів очищуються від `\/:*?"<>|#^[]`.
- Нотатки не засмічуються метаданими: YAML-заголовок порожній, якщо теги не
  передані явно.
- Секрети задаються лише через `wrangler secret`, у репозиторії їх немає.

## Що потрібно

- [Акаунт Cloudflare](https://dash.cloudflare.com/) (достатньо безкоштовного)
- Node.js 18+
- WebDAV-сховище. Для Koofr — **пароль застосунку**, не пароль акаунта
- Сховище Obsidian, синхронізоване з цим WebDAV (Koofr Sync, Remotely Save або
  десктопний клієнт Koofr)

## Встановлення

### 1. Дані WebDAV

Для Koofr: [koofr.eu](https://koofr.eu) → аватар → **Preferences → Password →
App passwords** → створити → скопіювати. Показується лише один раз.

Адреса WebDAV: `https://app.koofr.net/dav/Koofr`.

### 2. Встановлення

```bash
git clone https://github.com/RoboLask/obsidian-mcp-worker.git
cd obsidian-mcp-worker
npm install
```

> Потрібен [Node.js](https://nodejs.org/) 18 або новіший. Перевірте: `node -v`.
> Немає Git? На GitHub натисніть **Code → Download ZIP**, розпакуйте й запустіть
> `npm install` у цій теці.

Створювати `.dev.vars` для деплою **не потрібно**. Цей файл лише для локального
тестування (`npx wrangler dev`); `npm run setup` сам запитає все необхідне.

### 3. Увійти в Cloudflare

```bash
npx wrangler login
```

Відкриє браузер один раз. Копіювати API-ключі не потрібно.

### 4. Створити KV-простори

Потрібні два: лічильник записів і токени OAuth.

```bash
npx wrangler kv namespace create MCP_COUNTER
npx wrangler kv namespace create OAUTH_KV
```

Отримані `id` вставте у `wrangler.toml`, замінивши
`REPLACE_WITH_YOUR_MCP_COUNTER_ID` та `REPLACE_WITH_YOUR_OAUTH_KV_ID`.

### 5. Вказати адресу воркера

У `src/index.ts`:

```ts
const BASE_URL = "https://obsidian-mcp.example.workers.dev";
```

Замініть на свою адресу. Вона використовується в метаданих OAuth і має
збігатися з доменом, куди ви деплоїте.

### 6. Налаштувати шлях до сховища

У `wrangler.toml`:

```toml
VAULT_PATH = "/Obsidian"      # шлях у WebDAV до сховища (де лежить .obsidian/)
DEFAULT_TZ = "Europe/Warsaw"  # часовий пояс для назв денних нотаток
```

Не впевнені щодо `VAULT_PATH`? Спочатку задеплойте, потім викличте інструмент
`ping` — він покаже, скільки об'єктів бачить за цим шляхом.

### 7. Деплой

**Одна команда — рекомендовано:**

```bash
npm run setup
```

Запитає email і пароль застосунку WebDAV, згенерує пароль власника, задасть усі
три секрети й задеплоїть. Наприкінці надрукує адресу воркера й пароль
власника — збережіть пароль, він потрібен для підключення клієнта.

Працює однаково на Windows, macOS і Linux. Це невеликий скрипт Node.js, який
використовує вже встановлений Node.

**Або вручну:**

```bash
npx wrangler secret put KOOFR_EMAIL          # або логін WebDAV
npx wrangler secret put KOOFR_APP_PASSWORD   # або пароль WebDAV
npx wrangler secret put OWNER_PASSWORD       # пароль для сторінки входу
npx wrangler deploy
```

### 8. Підключити клієнт

**Claude** — відкрийте claude.ai у браузері (з телефона також працює):

1. **Settings → Connectors → Add custom connector**
2. URL: `https://<ваш-воркер>/mcp`
3. Авторизація: залиште типову (**OAuth**)
4. **Add** → вас перекине на сторінку входу → введіть `OWNER_PASSWORD`

Після підключення у вебі конектор з'явиться і в мобільному застосунку Claude.
Щоб асистент точно його використав, наберіть `@` у запиті й виберіть конектор.

### Інші клієнти

Сервер написаний і перевірений для **Claude** (веб і мобільний) — на той момент
це був єдиний клієнт із підтримкою власних віддалених MCP-конекторів через
OAuth. Інструкція вище розрахована на нього.

Але до Claude він не прив'язаний. Підійде будь-що, що вміє віддалений MCP:

- конектори **ChatGPT** (режим розробника, платні плани)
- **Claude Desktop** та інші десктопні MCP-хости через `mcp-remote`
- **Cursor**, **Windsurf**, підтримка MCP у **VS Code**
- **LibreChat**, **Open WebUI**, **Msty** та подібні self-hosted інтерфейси
- **mcp-inspector** і власні скрипти для налагодження

Вимоги скрізь однакові: Streamable HTTP за шляхом `/mcp` і OAuth authorization
code flow з PKCE. Вкажіть клієнту адресу воркера й дозвольте зареєструватися —
він потрапить на сторінку входу й попросить `OWNER_PASSWORD`.

Інструменти — звичайний MCP, тому конкретна модель не має значення. Різниця
лише в тому, як клієнт дає до них доступ: у Claude і ChatGPT є інтерфейс для
власних конекторів, частина десктопних хостів потребує запису в JSON-конфігу, а
self-hosted інтерфейси зазвичай читають список MCP-серверів зі своїх налаштувань.

## Як працюють завдання

`add_task` пише в розділ `## Задачи` / `## Tasks` денної нотатки, якщо він є,
інакше додає в кінець:

```markdown
## Задачі

- [ ] Подзвонити в банк ⏫ 📅 2026-11-14
- [ ] Купити молоко
```

`today_tasks` читає `Daily/<сьогодні>.md` і повертає незакриті пункти. З
`includeVault: true` обходить усе сховище (до `maxFiles`, типово 40) і також
повертає відкриті завдання з інших нотаток, відсортовані за строком.

## Обмеження

- `search_notes` читає файли по одному — повільно на дуже великих сховищах.
- Видалення й перейменування відсутні навмисно.
- Лише Streamable HTTP; застарілий HTTP+SSE не підтримується.

## Структура проєкту

```
setup.js         інтерактивний скрипт деплою (Windows / macOS / Linux)
src/index.ts     маршрутизація та обгортка OAuth-провайдера
src/tools.ts     опис MCP-інструментів
src/koofr.ts     WebDAV-клієнт (HEAD / GET / PUT / MKCOL / PROPFIND)
src/markdown.ts  назви файлів, frontmatter, дати
src/tasks.ts     парсер завдань Obsidian Tasks
src/login.ts     сторінка входу й підписані сесії
```

## Локальна розробка

```bash
npx wrangler dev
```

Потім викличте MCP-ендпоінт напряму. Для OAuth-потоку потрібен справжній
клієнт; для швидкої перевірки скористайтеся інструментом `ping` через асистента
або `npx wrangler tail`, щоб бачити запити.
